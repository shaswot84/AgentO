# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- **Reusable Security Probes (`packages/runtime`)**: Added typed capability/probe registries and independent cookie, cross-origin, authorization, XSS and SQL investigations with immutable, redacted evidence, isolated persona comparisons, bounded scanner ports and explicit collection limits. Probes report observations without vulnerability verdicts.
- **Probe Verification and Documentation**: Added registration, scope, lifecycle, cancellation, privacy and adapter-boundary regression coverage, opt-in vulnerable/fixed storefront and Chromium checks, and setup/usage documentation.
- **Application Model Frontend (`apps/frontend`)**: Added a read-only model explorer with endpoint search and filters, authentication/role claims, parameters, source handlers, resources and ownership, data-flow/database observations, cookie/CORS configuration, original evidence inspection and contributing-run provenance.
- **Retained Model Integration**: Persisted full framework/static contributions and public workflow identities/resources/signals, exposed backend model assembly through the local API, and added empty/partial/stale coverage states, incompatible-observation diagnostics, synthetic demo data, persistence/API regression tests and real-provider/browser checks. Updated frontend documentation and rebuilt browser assets.
- **Natural-language browser workflows (`apps/frontend`, `packages/workflow`)**: Connected free-form goals to bounded semantic planning with recipe priority, backend-only model configuration, recipes-only mode, profile-specific personas, local demo credential restrictions, and actionable preflight diagnostics. Persisted model usage, completion provenance, recent steps and final page metadata; corrected skipped/failed notifications and made diagnostics visible across result tabs. Added regression and browser integration coverage and setup documentation.
- **Project Deletion Feature (`apps/frontend`)**: Added project deletion capability across the frontend UI, client contracts, and local workspace service. Users can delete custom projects directly from project cards in the Applications list, from the Discovery overview, or from empty discovery states via a confirmation dialog with irreversible data warning and loading feedback. Added `deleteProject` to `AgentOClient`, implemented HTTP `DELETE /api/projects/:id` in `createLocalApi` and `LocalService` with scan-in-progress concurrency guards (`SCAN_IN_PROGRESS`), read-only protection for demo fixtures (`INVALID_INPUT`), atomic disk persistence in `Workspace`, and memory-session deletion in `createFixtureClient`. Added comprehensive unit, API, and client test coverage.
- **Demo Application 05 — Enterprise Cloud Ops Console (`demo-apps/demo-app-05`, `plugins/tools/e2e-browser`)**: Added a purpose-built single-page console application with client-side tab navigation (`Infrastructure Fleet`, `Threats & Triage`, `Tenancy & IAM`), in-page modal dialogs, and indirect domain terminology (`Examine Incident`, `Acknowledge & Escalate`) to stress-test dynamic LLM semantic browser planning. Added the `ops-console` target application profile, authentication strategy, responder/commander personas, and unit test suite.
- **Live LLM Unscripted Planning Verification (`plugins/tools/e2e-browser`)**: Added live end-to-end integration tests (`test/demo-app-03-llm.integration.test.ts`, `test/demo-app-05-llm.integration.test.ts`) proving that open-weight models (Ollama Cloud `gemma4:31b`) and OpenAI models autonomously navigate multi-step paths across both Demo App 03 (Audit Portal) and Demo App 05 (Cloud Ops Console) without hardcoded selectors, endpoint assumptions, or workflow recipes.
- **Open-Weight Action Key Normalization (`packages/workflow`)**: Added resilient key and property normalization in `parsePlannedAction` to handle open-weight model payload variations (`action` vs `actionType` aliases and omitted null fields) while strictly rejecting unexpected properties.
- **Ollama Cloud & OpenAI-Compatible Model Integration (`plugins/models/openai`, `.env`)**: Added support for OpenAI-compatible providers and gateways including Ollama Cloud (`https://ollama.com/v1/responses`) with model `gemma4:31b`, added a clean `.env.example` template, added an optional `endpoint` configuration to `OpenAIModelProviderOptions` with URL scheme validation, added resilient markdown code fence (` ```json `) stripping for open-weight model responses, added `createOpenAIModelProvider` for environment-driven instantiation, added unit and live integration tests, and enabled automatic root `.env` loading in the frontend local execution service.
- **Browser Workflow Layer Frontend Visibility (`apps/frontend`)**: Added a dedicated Browser Workflows view in the frontend workspace for inspecting automated browser execution results. Users can review goal statements, outcome badges (COMPLETED, FAILED, SKIPPED), duration, action counts, persona authentication and session reuse state, detected DOM page models and interactive elements, discovered attack-surface endpoints with parameters and roles, observed network traffic filtered by status or blocked origin scope, step-by-step action timelines, and evidence trails. Added seeded demonstration scenarios (`demo-shop`) covering storefront order browsing, session reuse, privileged administrative oversight, multi-page portal redirect/CSRF tracking, and strict scope guard boundary defense, along with live workflow execution against configured projects via Playwright integration, workspace persistence, and cross-navigation links from Scan Progress and Findings views.
- **Local Frontend Execution and Persistence (`apps/frontend`)**: Connected project, discovery, scan, finding, evidence, and remediation views to a same-origin loopback API in development and preview. Added atomic private disk storage, exclusive workspace ownership, interrupted-run recovery, real discovery/Semgrep execution with polled progress, and evidence-linked candidate guidance. Static candidates remain hypotheses; runtime verification is explicitly unavailable and demo fixtures stay labelled and read-only.
- **Frontend Integration Verification**: Added persistence, concurrency, failure, HTTP transport and request-boundary tests, plus an opt-in real Semgrep integration test. Updated setup and storage documentation.
- **Application Security Model (`packages/security-model`)**: Added immutable, framework-independent assembly of source, browser and public runtime observations, origin-aware endpoint deduplication and aliases, parameters, authentication/role claims, resource ownership, source handlers, data-flow candidates, database operations, cookie/CORS configuration and preserved evidence provenance.
- **Security Model Integration and Verification**: Added normalized contribution helpers, safe runtime metadata wrapping, conflict diagnostics and reference validation, package setup/usage documentation, unit coverage and real demo source integration checks. Existing core provider contracts can consume the resulting model.
- **Runtime Capabilities (`packages/runtime`)**: Added scoped single-exchange HTTP execution, bounded binary response collection and timings, structured header/cookie parsing, callback-scoped browser control, isolated expiring authentication sessions, and cookie/network observations without assessment rules or vendor imports.
- **Runtime Session Transfer and Verification**: Added private active-context cookie read/replace capabilities to the guarded browser interface, browser-to-HTTP and HTTP-to-browser session transfer, mocked lifecycle/isolation tests, and live HTTP/Chromium checks for Alice/Bob/Admin. Documented setup, limits, privacy boundaries, and supported authentication.
- **Optional Semantic Browser Planning (`packages/workflow`, `packages/core`)**: Added provider-independent model/page/action/history contracts, recipe-first workflow orchestration, constrained LLM proposals, deterministic scope and credential validation, bounded recovery and model budgets, and explicit completion provenance.
- **OpenAI Model Provider (`plugins/models/openai`)**: Added an optional bounded Structured Outputs provider with caller-selected model and backend credentials, cancellation, sanitized failures, token accounting, and mocked transport tests.
- **Semantic Workflow Safety and Verification**: Added fake-model unit and Chromium coverage for unfamiliar UI planning, prompt injection, private credential references, stale state, provider failures, recipe recovery, query-link navigation, nested storage redaction, and runtime scope narrowing. Browser capabilities remain deterministic and existing workflows remain supported.
- **Portability Demo Applications (`demo-apps/demo-app-03`, `demo-apps/demo-app-04`)**: Added standalone SSR Multi-Page Portal (`demo-app-03`) with HTML form 302/303 redirects, CSRF validation, and server-rendered DOM verification, and Modern Edge-Case SPA (`demo-app-04`) featuring multi-step login, `sessionStorage` token storage, and background WebSocket/Worker/CDN escape endpoints.
- **Portability Target Profiles & Edge-Case Verification (`plugins/tools/e2e-browser`)**: Added `portal` and `edge-spa` target profiles and workflow planners, expanded CLI `--target` options to include `portal` and `edge-spa`, and verified portability boundaries across unit and real-browser integration tests covering 302 redirects, multi-step authentication failures vs custom declarative strategy success, `sessionStorage` context isolation limits, and strict scope blocking of WebSockets and unapproved origins.
- **Cross-Project Browser Portability**: Added tool-independent target profiles, personas, authentication strategies, bounded page inspection and iterative workflow planning. Moved storefront assumptions into target configuration; retained recipes, structured plans, JSON export, and strict origin enforcement with isolated target/persona sessions.
- **Browser Portability Verification and Documentation**: Added a distinct JWT-backed purchases SPA fixture and configurable CLI target, normalized network provenance and safe headers, 44 unit tests and 31 real-browser tests across both applications. Documented configuration, supported authentication, and compatibility limits.
- **Browser Output File Export (`plugins/tools/e2e-browser`)**: Added `--output` CLI flag to write formatted observation records directly to a JSON file on disk alongside stdout, verified with unit and integration tests.
- **Browser Workflow Layer (`plugins/tools/e2e-browser`)**: Added `TesterArmyE2EAdapter` backed by pinned e2e/web/Chromium dependencies, trusted storefront goals, structured browser plans, isolated Alice/Bob/Admin sessions, verified memory/file authentication reuse, redacted immutable network/browser evidence, optional masked screenshots, and a standalone local-demo CLI. Exact-origin guards enforce redirects and block unsupported popup/worker/WebSocket traffic.
- **Browser Verification and Documentation**: Added setup, core registration, session/evidence boundaries, 25 unit tests, and 15 real-browser integration tests covering UI order API calls, authentication reuse/recovery, rejected logins, screenshots, CLI execution, and scoped navigation/request blocking. Updated root and core READMEs with the browser capability.
- **Project Re-Scan Options (`scripts/discover.mjs`, `apps/frontend`)**: Added `--rescan` (or `-r`) and `--all` (or `-a`) CLI flags to `scripts/discover.mjs` to automatically detect and re-scan all projects that have already been scanned with `discovery.json`. Integrated live "Re-scan repository" buttons and dev-bridge adapter execution into the frontend (`apps/frontend`), allowing instant re-discovery of loaded projects from the web interface.
- **Static Analysis Integration (`plugins/tools/semgrep`)**: Added a read-only Semgrep adapter, focused JS/TS XSS and SQL injection candidate rules, normalized source/sink evidence with AST and framework context, and a standalone JSON CLI. Static signals remain candidates requiring runtime verification.
- **Static Analysis Verification and Documentation**: Added pinned Semgrep installation instructions, core registration examples, execution limits and diagnostics, candidate-only limitations, unit/process tests, and real-tool demo plus unsafe/fixed JS/TS integration tests.
- **Discovery Automation CLI Script (`scripts/discover.mjs`)**: Added a dedicated CLI script allowing selective discovery execution against any selected demo project (e.g. `node scripts/discover.mjs demo-app-02`) or custom repository path, writing project-local `discovery.json` snapshots directly inside target directories.
- **Frontend Local Discovery Dev Bridge (`apps/frontend`)**: Added Vite dev server middleware (`/api/discover` and `/api/demo-apps`) and interactive UI controls in the New Project and Import Discovery dialogs to run discovery directly against local repository paths and quick-load demo projects with a single click.
- **Demo Application 02 (`demo-apps/demo-app-02`)**: Added a Fastify + JWT + PostgreSQL + Redis + Drizzle ORM microservice demonstrating multi-language (TypeScript, JavaScript, Python), multi-manifest (`package.json`, `contracts/package.json`), type-only import filtering, remote URL version masking, and custom CORS headers. Verifies the robustness of Project Discovery stack detection and graceful black-box mode fallback.
- **Express Framework Adapter (`plugins/frameworks/express`)**: Added read-only JS/TS extraction of mounted routes, request inputs, authentication/authorization guards, session/cookie/CORS configuration, and SQL operation metadata with normalized source evidence, redaction, bounded traversal, and incomplete-extraction diagnostics. Includes a standalone JSON CLI, real discovery/core integration, and 31 tests covering all 19 declared demo routes.
- **Express Adapter Documentation**: Added setup, API registration, evidence format, verification, and extraction limitations; updated root and discovery READMEs to link the implemented adapter.
- **AgentO Frontend (`apps/frontend`)**: Added a React + TypeScript workspace for project setup, validated saved discovery imports, stack and adapter summaries, and clearly labelled scan, finding, evidence, and remediation fixtures. Includes responsive layouts, keyboard-accessible forms, loading/error/empty states, a replaceable asynchronous client, and 41 client tests.
- **Frontend Documentation**: Added local development, build, verification, and integration instructions; documented session-only storage and backend execution boundaries in the frontend and root READMEs, and updated the discovery README's adapter milestone reference.
- **Project Discovery (`packages/discovery`)**: Implemented repository scanner that inspects manifests and source code to detect languages, frameworks (Express), dependencies, databases (SQLite), auth sessions, and middleware, selecting code-aware or black-box scanning mode.
- **Documentation**: Updated root `README.md` with `packages/discovery` reference and usage link.
